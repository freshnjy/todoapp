# 단계별 작업

한 번에 한 단계씩 진행한다. 각 단계가 끝나면 "확인 방법"대로 직접 확인한 뒤 커밋하고 다음으로 넘어간다.

2026-10-10에 네 단계를 모두 끝내고 서버에 반영했다. 새 작업을 시작할 때는 이 표 아래에 단계를 더하고, 무엇을 만드는지는 먼저 `docs/PRD.md`에 적는다.

| 단계 | 내용 | 선행 조건 | 상태 |
| --- | --- | --- | --- |
| 1-1 | 서버로 이전 (화면 파일만) | 없음 | 완료 (2026-10-10 서버 반영) |
| 1-2 | 자체 로그인과 서버 저장 | 1-1을 서버에서 확인 | 완료 (2026-10-10 서버 반영) |
| 2 | 반복 할 일(루틴) | 1-2, PRD의 "정해야 할 것" 확인 | 완료 (2026-10-10 서버 반영) |
| 3 | 해빗트래커 | 2, PRD의 "정해야 할 것" 확인 | 완료 (2026-10-10 서버 반영) |

1-1과 1-2를 나눈 이유: 1-1에서는 서버 쪽(systemd, nginx, 포트)만, 1-2에서는 앱 코드만 바뀐다. 문제가 생기면 원인이 어느 쪽인지 바로 알 수 있다.

## 1-1단계: 서버로 이전 (화면 파일만)

**만들 것**
- 화면 파일 세 개를 `frontend/`로 옮긴다. 내용은 바꾸지 않는다.
- `frontend/`를 그대로 내려 주는 FastAPI 앱과 `api/health`
- `requirements.txt`, `requirements-dev.txt`, `pytest.ini`, `.gitignore`
- systemd 유닛 예시(`127.0.0.1:8003`), nginx location 예시(`/todo/`)
- 서버에서 실행할 순서를 적은 `docs/deploy.md`
- 테스트: 화면 파일이 그대로 내려오는지, health, 화면 파일에 `/`로 시작하는 주소가 없는지

**하지 않을 것**: 로그인, 서버 저장, 화면 변경. 데이터는 여전히 브라우저(localStorage)에 있다.

**알아 둘 것**
- 앱에 로그인이 아직 없으므로, 이 단계에서만 nginx의 기존 비밀번호 창으로 `/todo/`를 막는다.
- 주소(출처)가 바뀌므로 예전 주소에서 쓰던 할 일은 보이지 않는다. 옮기지 않기로 했다.

**확인 방법**
- `pytest`가 모두 통과한다.
- 로컬: `uvicorn backend.app.main:app --port 8003` 후 `http://localhost:8003`에서 할 일을 추가·완료·수정·삭제할 수 있다.
- 서버: `docs/deploy.md`의 5번 확인이 모두 맞는다. 특히 시크릿 창에서 `/todo/`를 열면 비밀번호 창이 먼저 뜬다.
- 휴대폰에서 `https://jy-cockpit.duckdns.org/todo/`가 열리고, 기존 세 서비스(`/`, `/runcoach/`, `/bridge/`)가 전과 같이 동작한다.

## 1-2단계: 자체 로그인과 서버 저장

**만들 것**
- 자체 로그인: `api/session` (POST, GET, DELETE)과 서명된 기기 쿠키. JY Bridge의 `backend/app/auth.py`와 같은 방식 (HMAC 서명, 30일, 연속 5회 실패 시 60초 잠금). 쿠키 이름 `todo_session`, 기본 경로 `/todo/`. 쿠키의 Path와 Secure는 환경 변수로 바꿀 수 있게 해서 로컬에서도 동작하게 한다.
- 환경 변수: `TODO_PASSWORD`, `TODO_SESSION_SECRET`, `TODO_SESSION_DAYS`, `TODO_COOKIE_PATH`, `TODO_COOKIE_SECURE`, `TODO_DATA_DIR`. `.env.example`에 설명과 함께 적는다 (실제 값 없음).
- 인증이 없으면 화면 요청은 `login.html`로, API 요청은 401
- `frontend/login.html`과 화면 아래의 로그아웃 버튼
- 저장소(`store.py`): SQLite 파일 1개, 할 일 테이블
- 할 일 API (`docs/api.md`를 새로 만들어 형식을 적는다):
  - `GET api/todos` 목록
  - `POST api/todos` 추가
  - `PATCH api/todos/{id}` 내용·카테고리·완료 수정
  - `DELETE api/todos/{id}` 삭제
  - 완료 항목 일괄 삭제
- 화면(`app.js`)의 저장을 localStorage에서 API 호출로 바꾼다. 화면의 순서 규칙(새 항목은 위, 완료하면 그룹의 맨 아래)과 입력 검증(100자, 빈 값 거부)은 그대로 두고, 서버에서도 검증한다.
- 날짜 정리를 서버로 옮긴다: 완료한 날이 오늘(Asia/Seoul)보다 앞선 일회성 할 일은 목록에서 빠진다.
- 저장에 실패하면 화면에 알린다. 로그인이 풀려 401이 오면 로그인 화면으로 보낸다.
- `deploy/`와 `docs/deploy.md` 갱신: `.env` 만들기, systemd의 `EnvironmentFile`, nginx의 `/todo/`를 `auth_basic off`로 바꾸기, 데이터 폴더 권한과 백업 방법
- 테스트: 로그인 성공과 실패와 잠금, 인증 없는 API가 401인지, 할 일 추가·수정·삭제·완료, 입력 검증, 날짜가 바뀐 뒤 목록

**하지 않을 것**: 반복, 해빗트래커, localStorage 데이터 가져오기, 오프라인 동작.

**확인 방법**
- `pytest`가 모두 통과한다.
- 로컬에서 `.env`를 만들고(`CLAUDE.md`의 자주 쓰는 명령) 띄웠을 때, 틀린 비밀번호는 거부되고 맞으면 할 일 화면이 나온다.
- 시크릿 창에서 `api/todos`를 열면 401이 나온다.
- 한 브라우저에서 추가한 할 일이 다른 브라우저(또는 휴대폰)에서 보인다.
- 서버를 재시작해도 할 일이 남아 있다.
- 서버: `docs/deploy.md`의 "1-1단계에서 올리기"를 따라 한 뒤 6번 확인이 모두 맞는다.
- 코드와 문서에 비밀번호나 비밀 값이 적혀 있지 않다.

## 2단계: 반복 할 일(루틴)

`docs/PRD.md`의 "정해야 할 것 > 2단계 전"은 2026-10-10에 확정했다.

**만들 것**
- 저장 구조: 루틴 정의 테이블(이름, 카테고리, 반복 규칙, 시작일, 종료일)과 날짜별 수행 기록 테이블(루틴, 날짜)
- 반복 규칙 계산: 매일 / 요일 지정 / 매월 N일. "이 루틴이 이 날짜에 해당하는가"를 판단하는 함수 하나로 모은다. 매월 31일처럼 없는 날짜의 처리를 정해 테스트한다.
- API: 루틴 만들기·수정·종료, 날짜별 체크와 해제, 오늘 목록에 루틴 포함
- 화면: 추가·수정 폼의 반복 옵션, 오늘 목록의 루틴 표시, 루틴 관리(수정, 종료)
- 테스트: 규칙별 해당 날짜, 체크한 다음 날 다시 미완료인지, 종료한 루틴이 목록에서 빠지고 기록은 남는지

**하지 않을 것**: 해빗트래커 화면, 스트릭과 달성률 계산.

**확인 방법**
- `pytest`가 모두 통과한다.
- "매일" 루틴을 만들면 오늘 목록에 나오고, 체크한 뒤 서버 날짜가 바뀌면 다시 미완료로 나온다.
- "요일 지정" 루틴은 해당 요일에만 나온다.
- 일회성 할 일의 동작은 1-2단계와 같다.
- 서버: `docs/deploy.md`의 8번(데이터 백업)을 한 뒤 7번(새 버전 올리기)을 따른다. 새 테이블은 앱이 시작할 때 스스로 만든다.

## 3단계: 해빗트래커

`docs/PRD.md`의 "정해야 할 것 > 3단계 전"은 2026-10-10에 확정했다.

**만들 것**
- API: 기간(시작일~종료일)의 루틴별 날짜 상태(한 날, 안 한 날, 해당 없는 날), 연속 달성일, 달성률
- 화면: 주간·월간 그리드, 그리드에서 체크와 해제(지난 날짜 포함), 루틴별 스트릭과 달성률
- 휴대폰 폭에서 월간 그리드가 화면 밖으로 넘치지 않게 한다.
- 테스트: 스트릭 계산(쉬는 날, 오늘 아직 안 한 경우, 종료한 루틴), 달성률, 지난 날짜 수정

**확인 방법**
- `pytest`가 모두 통과한다.
- 오늘 목록에서 체크한 루틴이 해빗트래커에도 체크되어 있고, 반대도 같다.
- 지난 날짜를 고치면 스트릭과 달성률이 바로 바뀐다.
- 휴대폰에서 월간 보기를 열었을 때 가로 스크롤 없이 읽을 수 있다.
- 서버: `docs/deploy.md`의 8번(데이터 백업)을 한 뒤 7번(새 버전 올리기)을 따른다. 저장 구조는 바뀌지 않는다.
