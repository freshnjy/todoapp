## 1-1단계: 서버로 이전 (화면 파일만)

**만들 것**
- 화면 파일 세 개를 `frontend/`로 옮긴다. 내용은 바꾸지 않는다.
- `frontend/`를 그대로 내려 주는 FastAPI 앱과 `api/health`
- `requirements.txt`, `requirements-dev.txt`, `pytest.ini`, `.gitignore`
- systemd 유닛 예시(`127.0.0.1:8003`), nginx location 예시(`/todo/`)
- 서버에서 실행할 순서를 적은 `docs/deploy.md`
- 테스트: 화면 파일이 그대로 내려오는지, health, 화면 파일에 `/`로 시작하는 주소가 없는지

**하지 않을 것**: 로그인, 서버 저장, 화면 변경. 데이터는 여전히 브라우저(localStorage)에 있다.

**알아 둘 것**
- 앱에 로그인이 아직 없으므로, 이 단계에서만 nginx의 기존 비밀번호 창으로 `/todo/`를 막는다.
- 주소(출처)가 바뀌므로 예전 주소에서 쓰던 할 일은 보이지 않는다. 옮기지 않기로 했다.

**확인 방법**
- `pytest`가 모두 통과한다.
- 로컬: `uvicorn backend.app.main:app --port 8003` 후 `http://localhost:8003`에서 할 일을 추가·완료·수정·삭제할 수 있다.
- 서버: `docs/deploy.md`의 5번 확인이 모두 맞는다. 특히 시크릿 창에서 `/todo/`를 열면 비밀번호 창이 먼저 뜬다.
- 휴대폰에서 `https://jy-cockpit.duckdns.org/todo/`가 열리고, 기존 세 서비스(`/`, `/runcoach/`, `/bridge/`)가 전과 같이 동작한다.

## 1-2단계: 자체 로그인과 서버 저장

**만들 것**
- 자체 로그인: `api/session` (POST, GET, DELETE)과 서명된 기기 쿠키. JY Bridge의 `backend/app/auth.py`와 같은 방식 (HMAC 서명, 30일, 연속 5회 실패 시 60초 잠금). 쿠키 이름 `todo_session`, 기본 경로 `/todo/`. 쿠키의 Path와 Secure는 환경 변수로 바꿀 수 있게 해서 로컬에서도 동작하게 한다.
- 환경 변수: `TODO_PASSWORD`, `TODO_SESSION_SECRET`, `TODO_SESSION_DAYS`, `TODO_COOKIE_PATH`, `TODO_COOKIE_SECURE`, `TODO_DATA_DIR`. `.env.example`에 설명과 함께 적는다 (실제 값 없음).
- 인증이 없으면 화면 요청은 `login.html`로, API 요청은 401
- `frontend/login.html`과 화면 아래의 로그아웃 버튼
- 저장소(`store.py`): SQLite 파일 1개, 할 일 테이블
- 할 일 API (`docs/api.md`를 새로 만들어 형식을 적는다):
  - `GET api/todos` 목록
  - `POST api/todos` 추가
  - `PATCH api/todos/{id}` 내용·카테고리·완료 수정
  - `DELETE api/todos/{id}` 삭제
  - 완료 항목 일괄 삭제
- 화면(`app.js`)의 저장을 localStorage에서 API 호출로 바꾼다. 화면의 순서 규칙(새 항목은 위, 완료하면 그룹의 맨 아래)과 입력 검증(100자, 빈 값 거부)은 그대로 두고, 서버에서도 검증한다.
- 날짜 정리를 서버로 옮긴다: 완료한 날이 오늘(Asia/Seoul)보다 앞선 일회성 할 일은 목록에서 빠진다.
- 저장에 실패하면 화면에 알린다. 로그인이 풀려 401이 오면 로그인 화면으로 보낸다.
- `deploy/`와 `docs/deploy.md` 갱신: `.env` 만들기, systemd의 `EnvironmentFile`, nginx의 `/todo/`를 `auth_basic off`로 바꾸기, 데이터 폴더 권한과 백업 방법
- 테스트: 로그인 성공과 실패와 잠금, 인증 없는 API가 401인지, 할 일 추가·수정·삭제·완료, 입력 검증, 날짜가 바뀐 뒤 목록

**하지 않을 것**: 반복, 해빗트래커, localStorage 데이터 가져오기, 오프라인 동작.

**확인 방법**
- `pytest`가 모두 통과한다.
- 로컬에서 `.env`를 만들고(`CLAUDE.md`의 자주 쓰는 명령) 띄웠을 때, 틀린 비밀번호는 거부되고 맞으면 할 일 화면이 나온다.
- 시크릿 창에서 `api/todos`를 열면 401이 나온다.
- 한 브라우저에서 추가한 할 일이 다른 브라우저(또는 휴대폰)에서 보인다.
- 서버를 재시작해도 할 일이 남아 있다.
- 서버: `docs/deploy.md`의 "1-1단계에서 올리기"를 따라 한 뒤 6번 확인이 모두 맞는다.
- 코드와 문서에 비밀번호나 비밀 값이 적혀 있지 않다.

## 2단계: 반복 할 일(루틴)

`docs/PRD.md`의 "정해야 할 것 > 2단계 전"은 2026-10-10에 확정했다.

**만들 것**
- 저장 구조: 루틴 정의 테이블(이름, 카테고리, 반복 규칙, 시작일, 종료일)과 날짜별 수행 기록 테이블(루틴, 날짜)
- 반복 규칙 계산: 매일 / 요일 지정 / 매월 N일. "이 루틴이 이 날짜에 해당하는가"를 판단하는 함수 하나로 모은다. 매월 31일처럼 없는 날짜의 처리를 정해 테스트한다.
- API: 루틴 만들기·수정·종료, 날짜별 체크와 해제, 오늘 목록에 루틴 포함
- 화면: 추가·수정 폼의 반복 옵션, 오늘 목록의 루틴 표시, 루틴 관리(수정, 종료)
- 테스트: 규칙별 해당 날짜, 체크한 다음 날 다시 미완료인지, 종료한 루틴이 목록에서 빠지고 기록은 남는지

**하지 않을 것**: 해빗트래커 화면, 스트릭과 달성률 계산.

**확인 방법**
- `pytest`가 모두 통과한다.
- "매일" 루틴을 만들면 오늘 목록에 나오고, 체크한 뒤 서버 날짜가 바뀌면 다시 미완료로 나온다.
- "요일 지정" 루틴은 해당 요일에만 나온다.
- 일회성 할 일의 동작은 1-2단계와 같다.
- 서버: `docs/deploy.md`의 8번(데이터 백업)을 한 뒤 7번(새 버전 올리기)을 따른다. 새 테이블은 앱이 시작할 때 스스로 만든다.

## 3단계: 해빗트래커

`docs/PRD.md`의 "정해야 할 것 > 3단계 전"은 2026-10-10에 확정했다.

**만들 것**
- API: 기간(시작일~종료일)의 루틴별 날짜 상태(한 날, 안 한 날, 해당 없는 날), 연속 달성일, 달성률
- 화면: 주간·월간 그리드, 그리드에서 체크와 해제(지난 날짜 포함), 루틴별 스트릭과 달성률
- 휴대폰 폭에서 월간 그리드가 화면 밖으로 넘치지 않게 한다.
- 테스트: 스트릭 계산(쉬는 날, 오늘 아직 안 한 경우, 종료한 루틴), 달성률, 지난 날짜 수정

**확인 방법**
- `pytest`가 모두 통과한다.
- 오늘 목록에서 체크한 루틴이 해빗트래커에도 체크되어 있고, 반대도 같다.
- 지난 날짜를 고치면 스트릭과 달성률이 바로 바뀐다.
- 휴대폰에서 월간 보기를 열었을 때 가로 스크롤 없이 읽을 수 있다.
- 서버: `docs/deploy.md`의 8번(데이터 백업)을 한 뒤 7번(새 버전 올리기)을 따른다. 저장 구조는 바뀌지 않는다.

## 4단계: 묶음 (장보기 등)

`docs/PRD.md`의 "정해야 할 것 > 4단계 전"은 2026-10-11에 확정했다.

**만들 것**
- 저장 구조: `groups` 테이블(이름, 카테고리, 만든 시각)을 새로 만들고, `todos`에 `group_id`(없으면 일반 할 일)를 더한다. 이미 있는 `todos` 테이블에는 앱이 시작할 때 열을 스스로 더한다 (기존 할 일은 그대로 일반 할 일).
- API (`docs/api.md`에 형식을 적는다):
  - 묶음 목록, 만들기, 이름·카테고리 수정, 삭제 (삭제하면 남은 품목도 함께 지운다)
  - 완료 항목 일괄 삭제는 묶음 안의 완료 품목도 지운다.
  - 품목 넣기 `POST api/groups/{id}/items`. 쉼표로 나눠 여러 품목을 한 번에 만든다 (앞뒤 공백 제거, 빈 조각은 버림, 조각마다 100자 검증). 일반 할 일 추가(`POST api/todos`)는 그대로 두어 쉼표로 나누지 않는다.
  - 할 일 응답에 `group_id`를 더한다.
- 화면: 입력창 아래의 묶음 버튼(고르기, 새 묶음 만들기), 오늘 화면의 접힌 묶음 줄과 펼친 품목 목록, 묶음 이름 수정과 삭제, 등록 후 커서와 고른 묶음 유지, 화면을 열 때 입력창에 커서
- 진행률 카드와 카테고리 탭 개수에서 묶음의 품목을 뺀다.
- 테스트: 묶음 만들기·수정·삭제, 품목 추가와 쉼표 나누기(일반 할 일은 나누지 않는지), 완료한 품목이 다음 날 지워지고 묶음은 남는지, 없는 묶음에 넣으면 거부되는지, 기존 데이터베이스 파일에서 열이 더해지는지

- 필터: 카테고리 탭은 카테고리가 맞는 묶음만 보이고, 상태 필터는 펼친 품목에만 적용한다. 묶음을 지울 때는 확인을 한 번 묻는다.

**하지 않을 것**: 묶음 안의 묶음, 품목의 반복, 품목 순서 바꾸기, 홈 화면 아이콘(설치), JY Bridge에서 입력하기.

**확인 방법**
- `pytest`가 모두 통과한다.
- "장보기" 묶음을 만들고 고른 뒤 "우유, 계란, 두부"를 넣으면 품목 세 개가 생기고, 오늘 화면에 "장보기 (3)" 한 줄로 보인다.
- 묶음을 고르지 않고 "엄마께 전화, 은행 확인"을 넣으면 할 일 하나로 들어간다.
- 품목을 모두 체크하고 서버 날짜가 바뀌면 품목은 없어지고 "장보기" 묶음은 남아 있다.
- 품목을 넣고 체크해도 진행률 카드의 숫자가 바뀌지 않는다.
- 일회성 할 일, 루틴, 해빗트래커의 동작은 전과 같다.
- 서버: `docs/deploy.md`의 8번(데이터 백업)을 한 뒤 7번(새 버전 올리기)을 따른다. 저장 구조가 바뀌므로 백업을 꼭 먼저 한다.

## 5단계: 음성 입력

`docs/PRD.md`의 "정해야 할 것 > 5단계 전"은 2026-10-11에 확정했다.

**만들 것**
- 문장 가르기 함수 (서버, 저장소를 건드리지 않는 순수 함수): 받아 적은 문장과 묶음 이름 목록을 받아 "어느 묶음의 어떤 품목인지 / 일반 할 일인지 / 없는 묶음인지"를 돌려준다.
  - 묶음 이름은 문장 앞에서 찾는다. 띄어쓰기와 뒤에 붙는 "에"·"에다"는 무시하고 견준다. 이름이 겹치면(예: "장"과 "장보기") 긴 이름을 먼저 본다.
  - "○○에 △△ 추가해줘" 꼴인데 ○○이 묶음이 아니면 없는 묶음이다. 꼬리말이 없거나 "에"가 없으면 일반 할 일이다.
  - 묶음에 넣는 품목은 쉼표와 "랑"·"하고"·"그리고"에서 나눈다. 일반 할 일은 나누지 않는다.
  - "추가해줘"·"추가"·"넣어줘" 같은 꼬리말과 품목 뒤의 "을/를"을 뗀다. 어떤 말을 떼는지는 목록으로 두고 테스트한다. "도"는 떼지 않는다 ("포도"가 "포"가 된다).
  - 묶음 이름으로 시작하면 "에"와 꼬리말이 없어도 그 묶음에 넣는다. 처음에는 "에"나 꼬리말이 있어야 했는데, 휴대폰에서 음성 인식이 "에"를 자주 놓쳐 할 일로 들어가는 바람에 2026-10-11에 바꿨다. 이름 뒤의 "의", "애", "예", "엔"도 "에"처럼 뗀다.
- API `POST api/voice` (`docs/api.md`에 형식을 적는다): `{"text": "장보기에 우유 추가해줘", "category": "personal"}`를 받아 가른 뒤 바로 넣는다. 응답에 무엇을 했는지(묶음에 넣음 / 할 일로 넣음 / 없는 묶음)와 새로 만든 할 일을 담는다. 없는 묶음이면 아무것도 넣지 않는다. 품목 넣기는 지금의 검증(100자, 30개)을 그대로 쓴다. 인증은 쿠키 그대로다.
- 화면:
  - 입력 영역의 마이크 버튼, 듣는 동안의 표시와 받아 적은 글, 그만두기
  - 넣은 뒤의 알림 줄과 "취소" (5초. 지금의 `DELETE api/todos/{id}`로 방금 넣은 것을 지운다)
  - 없는 묶음 알림의 "할 일로 넣기" 버튼 (말한 문장 그대로 `POST api/todos`로 넣는다)
  - 없는 묶음, 권한 거절, 아무 말도 못 들음, 저장 실패를 알리는 문구
  - `?voice=1`로 열면 바로 듣기. 크롬이 터치를 요구하면 큰 마이크 버튼으로 바꾼다 (휴대폰에서 확인하고 정한다).
  - 음성 인식이 없는 브라우저에서는 마이크 버튼을 감춘다.
- 로그인 화면: `?voice=1`로 들어왔으면 로그인 뒤 같은 주소로 돌려보낸다.
- `docs/deploy.md`: 휴대폰 홈 화면에 바로 듣기 아이콘을 두는 방법 (9번)
- 테스트: 문장 가르기(묶음 있음, 묶음 이름 없음, 없는 묶음, 꼬리말과 조사, 겹치는 묶음 이름, 띄어쓰기), `api/voice`가 묶음과 일반 할 일을 맞게 넣는지, 없는 묶음일 때 아무것도 생기지 않는지, 인증 없으면 401인지, 빈 문장과 긴 문장 거부

**하지 않을 것**: 쓰기용 토큰과 앱 밖에서 부르는 API, 음성 비서(제미나이, 구글 어시스턴트) 연동, 말로 완료·삭제·수정하기, 말로 묶음이나 루틴 만들기, 서버에서 음성 인식하기, AI로 문장 해석하기, 앱처럼 설치(manifest, 서비스 워커).

**알아 둘 것**
- 음성 인식은 자동 테스트로 확인할 수 없다. `pytest`는 문장 가르기와 API만 본다. 마이크와 바로 듣기는 휴대폰에서 직접 확인한다.
- 브라우저의 음성 인식은 HTTPS에서만 동작한다. 로컬 확인은 `localhost`에서 PC 크롬으로 한다.
- 로그에 받아 적은 문장을 남기지 않는다.

**확인 방법**
- `pytest`가 모두 통과한다.
- 휴대폰에서 마이크 버튼을 누르고 "장보기에 우유 추가해줘"라고 말하면 "장보기 (N)"의 숫자가 하나 늘고, "장보기에 '우유' 추가함 · 취소"가 보인다.
- "취소"를 누르면 방금 넣은 우유가 없어진다.
- "치과 예약하기"라고 말하면 일반 할 일로 들어간다.
- "약국에 밴드 추가해줘"라고 말하면(약국 묶음이 없을 때) 아무것도 생기지 않고 알림이 보인다.
- 홈 화면 아이콘으로 열면 바로 듣기 시작한다 (또는 큰 마이크 버튼이 보인다).
- 마이크 권한을 거절하면 알림이 보이고, 손으로 입력하는 것은 전과 같다.
- 할 일, 묶음, 루틴, 해빗트래커의 동작은 전과 같다.
- 서버: 백엔드가 바뀌므로 `docs/deploy.md`의 8번(데이터 백업)을 한 뒤 7번(새 버전 올리기)을 따른다. 저장 구조는 바뀌지 않는다.

## 6단계: 화면 줄이기

`docs/PRD.md`의 "정해야 할 것 > 6단계 전"은 2026-10-11에 확정했다. 화면 파일만 바뀐다.

## 9단계: 묶음 없애고 음성을 메모로

## 10단계: 할 일에 메모 연결

2026-10-23 확정. 할 일을 완료하면 연결된 메모의 체크한 품목을 지우고, 루틴에는 메모를 붙이지 않는다. 자세한 것은 PRD의 "10단계" 표.

**만들 것**
- 서버: 연결 테이블 `todo_memos`(`todo_id`, `memo_id`). 할 일에 `memo_ids`(붙인 순서)를 담는다. `PUT api/todos/{id}/memos` `{"memo_ids": [...]}`로 연결을 통째로 바꾼다(없는 메모 id는 404, 같은 id는 한 번만). 할 일의 `done`이 거짓→참으로 바뀌면 연결된 메모마다 체크한 품목을 지우고 고친 시각을 바꾼다. 할 일·메모를 지우거나, "완료 항목 지우기"·날짜 정리로 할 일이 지워지면 연결도 지운다.
- 화면: 할 일 아래에 연결된 메모 줄 "📝 장보기 (3)". 누르면 품목이 펼쳐지고 체크·해제하면 메모 품목이 바뀐다. 할 일 수정 화면에 메모 버튼(붙이기·떼기), "저장"으로 글·카테고리와 함께 저장. 저장소의 메모를 펼치면 "🔗 할 일 이름". 완료로 체크할 때 지워질 체크 품목이 있으면 알림 없이 지운다.
- 테스트: 연결 바꾸기와 순서, 없는 메모, 완료 시 체크 품목 삭제(체크 안 한 것과 다른 메모는 그대로), 완료 해제는 되살리지 않음, 할 일·메모 삭제와 날짜 정리 뒤 연결 정리, 루틴에는 경로가 없음, Bridge 요약 그대로.

**하지 않을 것**: 루틴에 메모 붙이기, 입력 영역에서 바로 연결하기, 음성으로 연결하기, 품목을 다른 메모로 옮기기.
