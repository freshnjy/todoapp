# API

경로는 앱 기준이다. 실제 서버에서는 nginx가 앞에 `/todo`를 붙여 준다 (`/todo/api/todos`). 프런트엔드는 상대 경로로 호출한다 (`api/todos`).

## 공통
- 요청과 응답은 JSON (UTF-8).
- 공개 경로는 `api/health`, `api/session`(POST, GET), 로그인 화면, CSS·JS뿐이다. 나머지 API는 로그인하지 않으면 401 `{"detail": "로그인이 필요합니다."}`, 화면은 303으로 `login.html` (바로 듣기 주소 `?voice=1`로 들어왔으면 `login.html?voice=1`. 로그인하면 같은 주소로 돌아간다).
- 입력이 규칙에 맞지 않으면 422. 없는 할 일, 묶음, 루틴은 404.
- "오늘"은 서버가 Asia/Seoul 기준으로 정한다. 날짜는 `YYYY-MM-DD`.

## 세션

| 메서드 | 경로 | 내용 |
| --- | --- | --- |
| POST | `api/session` | `{"password": "..."}`. 맞으면 200 `{"authenticated": true}`와 쿠키. 틀리면 401. 연속 5번 틀리면 60초 동안 429 (`Retry-After` 초). 서버에 설정이 없으면 503 |
| GET | `api/session` | `{"authenticated": true \| false}` |
| DELETE | `api/session` | 로그아웃. 쿠키를 지운다 |

### 세션 쿠키
- 이름 `todo_session`, 값은 `발급시각.서명` (HMAC-SHA256, `TODO_SESSION_SECRET`). 서버에 세션을 저장하지 않는다.
- `HttpOnly`, `SameSite=Lax`, 유지 30일(`TODO_SESSION_DAYS`).
- `Path`는 기본 `/todo/`, `Secure`는 기본 켜짐. 로컬에서는 `TODO_COOKIE_PATH=/`, `TODO_COOKIE_SECURE=false`.

## 할 일

할 일 하나:

```json
{"id": 12, "text": "보고서 쓰기", "category": "work", "done": false, "group_id": null}
```

- `text`: 앞뒤 공백을 뗀 뒤 1~100자
- `category`: `work`(업무), `personal`(개인), `growth`(성장)
- `group_id`: 묶음의 품목이면 그 묶음의 id, 일반 할 일이면 `null`

| 메서드 | 경로 | 요청 | 응답 |
| --- | --- | --- | --- |
| GET | `api/todos` | | 200 `{"today": "2026-10-10", "todos": [...]}` |
| POST | `api/todos` | `{"text": "...", "category": "work"}` (`category`를 빼면 `work`) | 201 할 일 |
| PATCH | `api/todos/{id}` | `text`, `category`, `done` 중 바꿀 것만 | 200 할 일 |
| DELETE | `api/todos/{id}` | | 204 |
| POST | `api/todos/clear-done` | | 200 `{"deleted": 2}` (완료 항목 모두 삭제. 묶음 안의 완료 품목 포함) |

`GET api/todos`는 일반 할 일과 묶음의 품목을 함께 준다. 화면이 `group_id`로 나눠 보여 준다. `POST api/todos`는 항상 일반 할 일을 만들고, 쉼표가 있어도 나누지 않는다.

### 순서
`todos`는 서버가 정한 순서로 온다. 화면은 이 순서를 지키면서 미완료를 위, 완료를 아래로 나눠 보여 준다.
- 새 할 일은 맨 앞에 온다.
- `done`이 실제로 바뀐 할 일은 맨 뒤로 간다. 내용이나 카테고리만 고치면 자리가 그대로다.

### 날짜 정리
완료한 날이 오늘보다 앞선 할 일은 `GET api/todos` 때 지워진다. 오늘 완료한 것은 오늘 동안 남는다. 완료를 풀면 지워지지 않는다.

## 묶음

장보기처럼 품목이 여러 개인 것을 담는 틀. 묶음 하나:

```json
{"id": 2, "name": "장보기", "category": "personal"}
```

- `name`: 앞뒤 공백을 뗀 뒤 1~20자
- `category`: 할 일과 같은 값. 만들 때 빼면 `personal`

| 메서드 | 경로 | 요청 | 응답 |
| --- | --- | --- | --- |
| GET | `api/groups` | | 200 `{"groups": [...]}`. 만든 순서 |
| POST | `api/groups` | `{"name": "장보기", "category": "personal"}` | 201 묶음 |
| PATCH | `api/groups/{id}` | `name`, `category` 중 바꿀 것만 | 200 묶음 |
| DELETE | `api/groups/{id}` | | 204. 남아 있는 품목도 함께 지운다 |
| POST | `api/groups/{id}/items` | `{"text": "우유, 계란, 두부"}` | 201 `{"todos": [...]}` (만든 품목들) |

### 품목
- 품목은 `group_id`가 있는 할 일이다. 체크, 내용 수정, 삭제는 할 일의 `PATCH`/`DELETE api/todos/{id}`를 쓴다.
- `text`를 쉼표(`,` `，` `、`)로 나눠 품목을 만든다. 조각의 앞뒤 공백을 떼고 빈 조각은 버린다. 쉼표가 없으면 품목 하나다.
- 남는 조각이 없거나, 조각 하나가 100자를 넘거나, 전체가 1000자를 넘거나, 30개를 넘으면 422 (하나도 만들지 않는다).
- 새 품목은 적은 순서대로 목록의 맨 앞에 온다.
- 품목의 카테고리는 묶음의 것을 따른다. 묶음의 카테고리를 바꾸면 품목도 함께 바뀌고, 품목에 `category`를 보내도 바뀌지 않는다.
- 완료한 품목은 다른 할 일처럼 다음 날 지워진다. 묶음은 비어도 남는다.

## 저장소 (메모, 8단계)

그때그때 생각난 것을 남겨 두는 곳. 할 일과 따로 살고, 날짜가 바뀌어도 지우지 않는다. 메모 하나:

```json
{
  "id": 3,
  "title": "장보기",
  "body": "코스트코에서",
  "created_at": "2026-10-12T21:40:05+09:00",
  "updated_at": "2026-10-13T08:02:11+09:00",
  "items": [
    {"id": 7, "text": "우유", "done": true, "created_at": "2026-10-12T21:40:05+09:00"},
    {"id": 8, "text": "소고기", "done": false, "created_at": "2026-10-13T08:02:11+09:00"}
  ]
}
```

- `title`: 앞뒤 공백을 뗀 뒤 0~20자. 비우면 `null`(화면에서 "제목 없음"). 제목 있는 메모끼리는 같은 제목을 쓸 수 없다 (띄어쓰기와 대소문자는 무시하고 견준다. "장 보기" = "장보기"). 제목 없는 메모는 여러 개 있을 수 있다.
- `body`: 2000자까지. 줄바꿈을 쓸 수 있다. 끝의 공백과 빈 줄은 뗀다.
- 시각은 Asia/Seoul. 앞 10자가 그날의 날짜다. `updated_at`은 제목, 글, 품목(넣기, 고치기, 체크, 지우기)이 바뀔 때마다 바뀐다.
- 목록은 마지막으로 고친 메모가 앞에 온다.

| 메서드 | 경로 | 요청 | 응답 |
| --- | --- | --- | --- |
| GET | `api/memos` | | 200 `{"memos": [...]}` (품목 포함) |
| POST | `api/memos` | `{"title": "장보기", "body": "", "items": "우유, 소고기"}` 모두 뺄 수 있다 | 201 메모 |
| PATCH | `api/memos/{id}` | `title`, `body` 중 바꿀 것만. `title`에 `null`이나 빈 글이면 제목을 지운다 | 200 메모 |
| DELETE | `api/memos/{id}` | | 204. 품목도 함께 지운다 |
| POST | `api/memos/{id}/items` | `{"text": "두부, 계란"}` | 201 메모 |
| PATCH | `api/memos/{id}/items/{item_id}` | `text`, `done` 중 바꿀 것만 | 200 메모 |
| DELETE | `api/memos/{id}/items/{item_id}` | | 200 메모 |
| POST | `api/memos/{id}/clear-done` | | 200 메모. 체크한 품목을 지운다 |

- 품목을 넣을 때는 묶음과 같은 규칙으로 쉼표에서 나눈다 (조각 100자, 전체 1000자, 30개까지. 넘으면 하나도 넣지 않고 422). 새 품목은 메모의 맨 아래에 적은 순서대로 붙는다.
- 체크해도 품목의 자리는 그대로이고, 지우지 않는다. 체크한 품목은 `clear-done`을 부를 때만 지운다.
- 거절: 같은 제목 409, 제목·글·품목이 모두 빈 메모(만들 때와 고친 결과) 422, 길이 초과 422, 없는 메모나 그 메모의 것이 아닌 품목 404.
- 품목을 하나씩 지워 메모가 비는 것은 막지 않는다.
- 할 일의 날짜 정리, "완료 항목 지우기", 진행률, `api/bridge-summary`는 메모를 보지 않는다.

## 음성 입력

브라우저가 받아 적은 문장을 서버가 규칙으로 갈라 바로 넣는다. 음성 인식은 서버가 하지 않는다. 받은 문장은 로그에 남기지 않는다.

| 메서드 | 경로 | 요청 | 응답 |
| --- | --- | --- | --- |
| POST | `api/voice` | `{"text": "장보기에 우유 추가해줘", "category": "personal"}` | 아래 표 |

- `text`: 받아 적은 문장. 1000자까지. 앞뒤 공백과 끝의 마침표는 떼고, 이어진 공백은 하나로 줄인다.
- `category`: 일반 할 일로 들어갈 때 쓸 카테고리 (빼면 `work`). 화면이 키워드 자동 분류로 골라 보낸다. 묶음의 품목은 묶음의 카테고리를 따른다.

| 문장 | 응답 |
| --- | --- |
| 이미 있는 묶음 이름으로 시작한다 ("에"나 꼬리말이 없어도 된다) | 201 `{"result": "group", "name": "장보기", "text": "...", "group": 묶음, "todos": [새 품목...]}` |
| "○○에 △△ 추가해줘" 꼴인데 ○○이 묶음이 아니다 (○○은 20자까지) | 200 `{"result": "unknown_group", "name": "약국", "text": "약국에 밴드 추가해줘", "group": null, "todos": []}`. 아무것도 넣지 않고 묶음도 만들지 않는다 |
| 그 밖 | 201 `{"result": "todo", "name": "", "text": "...", "group": null, "todos": [새 할 일]}`. 말한 문장 그대로 할 일 하나로 넣는다 (나누지 않고, 꼬리말도 떼지 않는다) |

`text`는 다듬은 문장이다. 없는 묶음일 때 화면이 "할 일로 넣기"에 이 글을 쓴다 (`POST api/todos`).

### 문장 가르기
- 묶음 이름은 문장 앞에서 찾고 띄어쓰기는 무시한다 ("장 보기에"도 "장보기"). 이름 뒤의 "에", "에다", "에다가", "에는", "에도"는 뗀다. 이름이 겹치면("장"과 "장보기") 긴 이름을 먼저 본다.
- "에"나 꼬리말이 없어도 묶음 이름으로 시작하면 그 묶음에 넣는다 ("짐싸기 여권"). 음성 인식이 "에"를 빠뜨리거나 "의", "애", "예", "엔"으로 받아 적는 일이 잦아서, 이름 뒤의 이런 글자도 "에"처럼 뗀다. 그래서 묶음 "운동"이 있으면 "운동 가기"도 그 묶음에 들어간다 (알림의 "취소"로 되돌린다). 묶음 이름만 말하면 일반 할 일이다.
- 꼬리말: "추가", "추가해", "추가하기", "넣어", "적어", "담아"와 그 뒤의 "줘", "주세요", "줄래". 앞의 "좀"도 함께 뗀다.
- 품목은 쉼표와 "랑"·"이랑"·"하고"·"그리고"에서 나눈다 ("우유랑 계란하고 두부" → 세 개). 마지막 품목 끝의 "을/를"은 받침이 맞을 때만 뗀다 ("마늘을" → "마늘", "노을"은 그대로).

### 거절 (422, `detail`에 이유)
- 빈 문장, 1000자를 넘는 문장
- 묶음 이름만 있고 품목이 없다 ("장보기에 추가해줘")
- 품목 하나나 할 일이 100자를 넘는다, 품목이 30개를 넘는다

## 루틴 (반복 할 일)

루틴 하나:

```json
{
  "id": 3,
  "text": "영어 단어",
  "category": "growth",
  "rule": {"type": "weekly", "days": [0, 2, 4]},
  "due_today": true,
  "done_today": false
}
```

- `text`, `category`: 할 일과 같은 규칙
- `due_today`: 오늘이 이 루틴을 하는 날인지. `done_today`: 오늘 했는지

### 반복 규칙 (`rule`)

| 모양 | 뜻 |
| --- | --- |
| `{"type": "daily"}` | 매일 |
| `{"type": "weekly", "days": [0, 2, 4]}` | 요일 지정. `0`=월 … `6`=일. 하나 이상 |
| `{"type": "monthly", "day": 25}` | 매월 N일 (1~31). 그 달에 없는 날짜면 그 달의 마지막 날 |

서버는 `days`를 정렬하고 겹친 값을 뺀다. 규칙에 필요 없는 값은 버린다.

| 메서드 | 경로 | 요청 | 응답 |
| --- | --- | --- | --- |
| GET | `api/routines` | | 200 `{"today": "2026-10-10", "routines": [...]}`. 종료하지 않은 루틴을 만든 순서로 |
| POST | `api/routines` | `{"text": "...", "category": "growth", "rule": {...}}` | 201 루틴 |
| PATCH | `api/routines/{id}` | `text`, `category`, `rule` 중 바꿀 것만 | 200 루틴 |
| POST | `api/routines/{id}/end` | | 204. 오늘부터 목록에서 빠진다 |
| PUT | `api/routines/{id}/logs/{날짜}` | | 204. 그 날짜에 했다고 적는다 |
| DELETE | `api/routines/{id}/logs/{날짜}` | | 204. 그 날짜의 기록을 지운다 |

### 규칙을 바꿀 때
`rule`을 바꾸면 오늘부터 적용된다. 지난 날짜가 하는 날이었는지는 그때의 규칙으로 판단한다. 같은 날 여러 번 바꾸면 마지막 것만 남는다.

### 수행 기록
- 기록은 (루틴, 날짜)마다 하나다. 같은 요청을 두 번 보내도 결과가 같다.
- 내일 이후의 날짜, 날짜 모양이 아닌 값은 422.
- 그날이 하는 날이 아니면 422 (규칙상 쉬는 날, 루틴을 만들기 전, 종료한 날부터).
- 종료한 루틴도 종료 전 날짜의 기록은 고칠 수 있다. 종료한 루틴의 수정과 재종료는 404.
- 할 일과 달리 루틴은 날짜가 바뀌어도 지워지지 않는다. `api/todos/clear-done`도 루틴을 건드리지 않는다.

## JY Bridge용 요약 (7단계)

| 메서드 | 경로 | 응답 |
| --- | --- | --- |
| GET | `api/bridge-summary` | 200 아래 모양 |

```json
{
  "date": "2026-10-11",
  "routines": {"due": 5, "done": 2, "remaining": ["스트레칭", "영어 단어", "독서"]},
  "todos": {"remaining_count": 3, "remaining": ["치과 예약하기", "보고서 초안", "택배 보내기"]}
}
```

- 인증은 헤더 `Authorization: Bearer {TODO_BRIDGE_TOKEN}`뿐이다. 상수 시간 비교(`secrets.compare_digest`). 헤더가 없거나 틀리면 401. 로그인 쿠키가 있어도 토큰이 없으면 401이다.
- `TODO_BRIDGE_TOKEN`이 비어 있으면 어떤 요청에도 401이다 (꺼진 상태).
- 이 토큰은 이 경로에서만 통한다. 다른 API는 전과 같이 쿠키만 받는다.
- 조회만 한다. 아무것도 지우거나 고치지 않는다 (`GET api/todos`의 날짜 정리를 하지 않는다).
- `date`: 서버의 오늘 (Asia/Seoul).
- `routines.due`: 오늘 하는 루틴 수. `done`: 그중 오늘 한 수. `remaining`: 아직 안 한 루틴의 이름, 앱의 "오늘의 루틴" 순서대로. 종료한 루틴과 오늘 하는 날이 아닌 루틴은 세지 않는다.
- `todos.remaining_count`: 완료하지 않은 일반 할 일 수. `remaining`: 그 이름, 앱 목록 순서대로. 묶음의 품목(`group_id`가 있는 것)은 세지 않는다.
- `remaining`은 각각 10개까지만 보낸다. 개수(`due`, `done`, `remaining_count`)는 전체를 센다.
- 로그에 이름을 남기지 않는다.

```json
{
  "today": "2026-10-10",
  "start": "2026-10-05",
  "end": "2026-10-11",
  "routines": [
    {
      "id": 3,
      "text": "영어 단어",
      "category": "growth",
      "rule": {"type": "weekly", "days": [0, 2, 4]},
      "ended": false,
      "days": ["done", "off", "missed", "off", "done", "off", "off"],
      "streak": 1,
      "done": 2,
      "due": 3
    }
  ]
}
```

- `routines`: 그 기간에 하루라도 살아 있던 루틴. 종료한 것도 들어간다 (`ended`). 만든 순서.
- `rule`: 가장 최근 규칙. 지난 날짜의 상태는 그때의 규칙으로 계산한다.
- `days`: `start`부터 `end`까지 하루에 하나씩.

| 값 | 뜻 |
| --- | --- |
| `done` | 한 날 |
| `missed` | 하는 날이었는데 안 한 지난 날 |
| `pending` | 오늘이 하는 날이고 아직 안 했다 |
| `off` | 하는 날이 아니다 (쉬는 날, 만들기 전, 종료한 날부터) |
| `upcoming` | 아직 오지 않은 하는 날 |

- `streak`: 오늘까지 이어진 연속 달성일. 쉬는 날은 건너뛴다. 오늘이 `pending`이어도 어제까지의 연속을 유지한다. `missed`에서 끊긴다. 종료한 루틴은 0. 보고 있는 기간과 상관없이 전체 기록으로 센다.
- `done`, `due`: 이 기간의 한 날 수와 하는 날 수(`done` + `missed`). `pending`과 `upcoming`은 세지 않는다.

칸을 고칠 때는 루틴의 `PUT`/`DELETE api/routines/{id}/logs/{날짜}`를 쓴다. `done`, `missed`, `pending`인 날만 고칠 수 있다.
